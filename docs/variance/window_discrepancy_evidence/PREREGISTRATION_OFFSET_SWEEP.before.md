The sampling unit is one controller-origin **physical shot epoch**, not one schedule refinement or banner read. Any amendment must be dated and frozen before inspecting the new verdicts. Do not change exclusions, models, peers, or thresholds after seeing grade-by-arm/offset results.

## 0. Acquisition, cohort, and locked analysis order

1. The owner declares the one spot/court and starts the two switches together. The launcher sets `ORION_ONSET_FF_AB=0.2:10:1,0.45:40:0` and `ORION_DEV_FIRE_OFFSET_SWEEP=uniform:-25:25`; the latter hook is compiled out in production builds. **Verify** `DEV FIRE OFFSET SWEEP ARMED`, both valid `ab_arm` values, and a live probe `meta.json`/nonempty `packets.csv` before treating any run as the planned experiment. `Start-Process` alone is not proof the probe collected packets. Record executable/build hash, settings hash, log paths, session IDs, capture directory, court/spot, and start/end UTC. A missing hook or failed probe cannot be imputed.
2. Freeze the first **100 consecutive physical press epochs** after the start marker, including pre-randomisation disarms, post-assignment disarms, in-tick releases, missing banners, and FF cold starts. A second block of the next 100 is a prespecified precision extension, not an effect-triggered optional stop. Report every transition: press → dev draw → FF arm → scheduled release → attributed banner. Both assignments occur in the scheduled-fire path, **not at the physical press**; never retroactively assign an arm or offset to a press that never reached that path. Do not continue only until 100 favourable graded shots appear.
3. Primary grade cohort: online `shot_record` with unique `(session, epoch)`, `shot_type=Standstill` (no later fade upgrade), `outcome=released`, finite `press_ts_ms`, `release_ms`, `release_after_press_ms`, and banner `timing∈{EARLY,EXCELLENT,LATE}`; owner-declared same-spot run; exclude an **explicitly contested** banner coverage cell. Missing coverage is retained but counted separately, not silently labelled OPEN. Repeat the analysis restricted to explicit `OPEN/WIDE OPEN` or a pre-verdict independent open annotation. If >20% are explicitly contested or >50% lack both coverage and independent annotation, no “open-shot” generalisation. Report distance distribution; do not outcome-filter on distance or onset tails.
4. Order of analysis is fixed: **identity/attrition → randomisation/delivery fidelity → ordinal ruler → FF ITT → width → network**. A failed earlier gate prevents a later causal/ceiling claim, although descriptive results remain reportable.

## 1. Exact joins and the offset first stage

**Record identity.** `shot_record.session` plus `shot_record.epoch` is the physical-shot key. Native `releaseSeq` is a *different* monotone release counter; never equate it to the JSONL `seq`. Partition native logs by process launch/reset, de-duplicate identical forwarded lines, and use UTC timestamps. A `Release onsetff` line supplies `physical_epoch`, `shot_attempt`, `seq`, `applied_ms`, and `scheduled`. Match it to exactly one record with the same physical epoch whose release timestamp is within **150 ms** of that line and whose `[press_ts_ms, closed_ts_ms]` interval contains it. Reject ambiguous/reused-epoch matches rather than nearest-guessing. Within that process partition, match `Release devoffset` and `Scheduled fire` by native `(seq, shot_attempt where present)` and the same release-time window; require unique values. This accommodates release-counter resets and overlapping record files.

**Assignment versus command.** Match `DEV FIRE OFFSET DRAW` by `shot_attempt` and interval. Call its `offset_ms` **Z** (planned draw). Match all `DEV FIRE OFFSET APPLIED` lines for that attempt only as a refinement audit: repeated schedule attempts can differ, and the last printed one need not be the token that fired. The authoritative locally carried dev displacement **D** is `Release devoffset.applied_ms`; its `scheduled=0` value is 0, not an effective −25…+25 treatment. The authoritative final FF displacement **F** is `Release onsetff.applied_ms`, likewise 0 on an in-tick release. Recover the FF assignment **A** from all `ONSET FF: ... physical_epoch=... ab_arm=...` lines for that record; require exactly one consistent arm in `{0,1}` and record `one_sided`, `gain`, `clamp_ms`, `reason`, reference/sample count. For covariate adjustment, use the last pre-release `ONSET FF dev_ms` only when its `ref_ms≥0` and `n≥4`; otherwise set deviation to 0 and add a reference-unavailable indicator, without dropping cold shots. Never infer A from F=0 (cold or one-sided shots can have zero effect). Require the release's `shot_attempt` to map to the matching draw and FF line; quarantine otherwise. Join `Release attribution` and `Release timing` by native `seq`/process and release time, not JSONL `seq`.

**Multiple attempts.** Count distinct `shot_attempt`/Z values per physical epoch. The dev hook draws per arm token, not per physical epoch; the FF arm should remain constant per physical epoch. Preserve the **first** draw as the intention-to-treat assignment for all-attempt/attrition reporting and the **release-carried** D for the conditional grade model. If more than **2%** of physical epochs have distinct dev draws or any epoch changes FF arm, the purported two-factor shot-level randomisation fails: report the data but do not use the delivered-only offset as a causal ruler.

**Fidelity gate, before grade fits.** On `scheduled=1` releases, at least **95%** must have `|D−Z_final|≤0.25 ms`; report clipping, in-tick release, abort, and missing-banner rates by negative/positive Z halves and A. More than a **10-percentage-point** grade-availability difference across Z halves or A means outcome selection is material and the graded-only ruler is not declared causal. Independently regress the record's local meter-relative release `H=release_after_press_ms−onset_ms` on Z with arm, onset deviation, and shot-order terms fixed in advance; report HC3-robust slope `λ_Z` and a block-by-20-shots bootstrap. Pass local **equivalence** only if its 90% CI lies entirely inside **[0.8,1.2] ms released per ms drawn**. A CI wholly below 0.8 is a fidelity failure; a CI spanning the limits is unresolved, not a pass. Repeat against D, and report `Scheduled fire.deltaMs` (p50, p95 absolute; p95 >5 ms flags local scheduler instability). This tests the *local release command* independently of the displacement log. Neither this regression nor `net_join` alone proves that the PS5 received a particular input packet.

**Eligibility gate.** Require ≥90% unambiguous release/arm/draw joins among graded scheduled cohort, ≥80% of all-attempt FF-arm assignments, both offset signs, and ≥8 EARLY plus ≥8 LATE labels for an unconstrained ordinal fit. Failures are missing/inconclusive, never zero effects. Do not replace the prespecified 200/60 ms historical outlier filters here: those were observational filters; random ±25 ms tails and all valid outcomes belong in this randomised experiment. Impossible/nonfinite timestamps are logged as protocol failures, not silently trimmed.

## 2. Millisecond ruler: estimand, fit, and expected precision

Only after fidelity passes, fit the graded scheduled cohort by maximum likelihood. Let `A=0/1`, `D` be release-carried dev displacement in ms (positive = later), and `Y=EARLY/EXCELLENT/LATE`. Define a **current-pipeline effective**, not server-only, normal-error model:

```text
L = c − W/2; U = c + W/2; μ_i = D_i + δ A_i
P(EARLY_i)     = Φ((L − μ_i)/σ)
P(EXCELLENT_i) = Φ((U − μ_i)/σ) − Φ((L − μ_i)/σ)
P(LATE_i)      = 1 − Φ((U − μ_i)/σ)
```

Estimate `c` (band centre relative to zero dev/arm 0), `W>0` (effective EXCELLENT width), `σ>0` (effective per-shot residual SD under the current pipeline), and nuisance arm shift `δ`. Fix the coefficient of **delivered** D to 1 only after the fidelity gate; refit it as a sensitivity parameter and show its CI. Give profile-likelihood 95% CIs for `c,W,σ` and `p_max=2Φ(W/(2σ))−1`, with a parametric-bootstrap interval if the profile is irregular or an estimate reaches a numerical boundary. Do not subtract onset variation from this already-conditional σ again. Do not call it uplink/server jitter. Check five prespecified Z bins (`[-25,-15),[-15,-5),[-5,5),[5,15),[15,25]`): use Pearson's sum of `(observed−expected)²/expected` over the 15 bin×grade cells, where expected counts sum each shot's fitted probability, and obtain the lack-of-fit p-value from **2,000 parametric simulations with a complete refit each time**; **p<0.05 rejects a single fixed band/normal noise ceiling**. A prespecified sensitivity adds centred onset and linear shot order and lets arm interact with onset; changes >20% in `W` or `σ` make the pooled ruler context-dependent, not definitive.

**Precision forecast, not a result.** Fisher information for uniform delivered offsets ±25 ms, 50/50 arms with no true arm shift, historical `c≈−7.4`, `W=94.39`, `σ=43.54`, 100% graded/fidelitous shots, and the four-parameter model above gives approximately:

| Graded n | Expected EARLY/LATE | SE(c) | SE(W) | SE(σ) | Approx. 95% half-width of `p_max` |
|---:|---:|---:|---:|---:|---:|
| 100 | 12 / 19 | 7.8 ms | **33.9 ms** | **16.2 ms** | **9.3 percentage points** |
| 200 | 24 / 39 | 5.5 ms | **23.9 ms** | **11.4 ms** | **6.6 points** |

These are **optimistic lower-bound errors**: dropouts, uneven arms, width variation, first-stage attenuation, and non-normal noise worsen them. **100 is too few** for a useful separate estimate of sigma or band width, or a credible mid-80s ceiling decision. **200 is still weak** for `W` versus `σ`; it might bound their ratio under a demonstrably well-fitting fixed-band model. Do not report a narrow Wald CI if a profile CI is unbounded. The original 72.2% is a prior benchmark to falsify, not a value to constrain the fit toward.

## 3. Onset-feedforward A/B and shipping rule

The primary **assignment-based policy-success** contrast is `Δ_sweep=P(released with an observed EXCELLENT banner | A=1)−P(released with an observed EXCELLENT banner | A=0)` over the planned offset sweep. Its denominator is **every target-Standstill physical epoch with a logged A assignment**, including subsequent aborts, in-tick releases, and missing banners; those count as policy non-success, not as EARLY/LATE. Pre-assignment disarms are outside the randomised denominator and appear separately in the full 100-press funnel. The secondary *graded-only* EXCELLENT contrast uses only observed banner grades and is explicitly conditional on grade availability, **not ITT**; compare its direction with the primary. Report EARLY/LATE among graded shots and missing-banner/abort differences over all assigned shots too. The **primary estimator** is the raw arm-1 minus arm-0 policy-success proportion; use an exact arm-label permutation test conditional on observed arm counts for the no-effect null and a two-sided 95% Newcombe-Wilson score interval (equivalently 97.5% one-sided bounds) for its risk difference. The prespecified adjusted sensitivity is logistic-regression g-computation with A, Z, Z², logged pre-arm onset deviation/reference-unavailable indicator, and shot order; standardise both arms over the same observed covariate distribution and give a 10,000-resample physical-epoch bootstrap interval. No per-shot result is counted twice. Secondary: warm-reference shots (`ONSET FF n≥4` before that shot), and the arm×onset-deviation interaction. Compare actual F by arm and deviation to confirm that the treatments physically separate; a zero-displacement arm is still assigned to its arm.

At EXCELLENT probability ~0.7 and balanced arms, an unadjusted arm risk difference has approximate **95% half-width ±18 points at total n=100** and **±13 points at n=200**. A real +3–5-point gain is not resolvable here; an idealised two-arm design needs roughly **2,600 total graded shots for 80% power at +5 points** (more for +3), before session clustering or sweep interaction. This run can reject a large harm or expose implementation failure, but **cannot by itself justify shipping arm 1**.

Shipping arm 1 requires all of: (i) verified FF assignment and materially different delivered F; (ii) a **97.5% upper bound <+2 percentage points** on the arm-1 minus arm-0 abort/missing-banner rate and an analogous **upper bound <+3 points** on EARLY among all assigned shots (an ungraded shot is not relabelled EARLY); (iii) **a separate no-sweep, production-equivalent randomised confirmation across ≥5 sessions**, with point policy-success gain ≥5 points and a session-clustered 97.5% lower confidence bound >+2 points, without a conflicting graded-only result; and (iv) a code/release gate proving the production path can actually deliver the winning early offset. If these fail or remain uncertain, retain arm 0 and gather more data. The sweep A/B estimates an effect **under deliberate ±25 ms mistiming**; it is not automatically the no-sweep deployment effect. A plain `onset_ff_gain=.45, clamp=40` settings change remains capped at 15 ms earlier outside the A/B path.

## 4. Green-window-width hypothesis

`Release attribution: greenWidth=` is a **release snapshot**, not a latched width at the first confirmation. `greenConfirmMs` is meter-elapsed at first confirmation. Match attribution to the release as above and, using `Release timing.appearToRelMs`, call it *confirmed before fire* only when `greenConfirmed=1`, `greenWidth>0`, `greenConfirmMs≥0`, and `appearToRelMs−greenConfirmMs≥20 ms`. This proves confirmation preceded release, **not** that the reported width was already stable. Because D can change the release time, release-snapshot width is potentially **post-treatment**; its interaction with D is only exploratory until pre-decision width is established. A label-blinded frame/video audit of the first 40 eligible shots, selected across Z quartiles and arms, must show the first-confirmed versus release widths differ by ≤0.2 pp at the median and ≤0.5 pp at the 95th percentile; additionally, the 90% CI for the slope of release width on Z must lie within **±0.02 pp per ms**. If frames are unavailable or either check fails, report association only and do not build a width-conditioned aim from this field. Predeclare primary plausible widths **0.5–5.0 percent points** (prior report flags >5 as suspect), and report exclusions and a full-range sensitivity without moving the range after grades. Need ≥60 valid widths with an interquartile span ≥1.0 pp and ≥20 shots in each narrow/wide quartile; otherwise the width test is inconclusive.

If the pre-decision gate passes, fit the same ordinal probabilities with `c(w)=c0+η(w−w0)`, `W(w)=W0+κ(w−w0)`, and `μ_i=[1+γ(w−w0)]D_i+δA_i`, where `w0` is the training median. The single confirmatory width test is a **3-df likelihood-ratio test of η=κ=γ=0 at p<0.025**; report the `D×width` coefficient γ, its profile interval, and the derivative of each verdict probability with respect to D at the narrow/wide quartiles. Check the local first-stage H-on-Z slope by width quartile too: a changing actuator slope is **not** evidence of a changing grade band. Show predicted EARLY/EXCELLENT/LATE curves at D=−25,0,+25 for the 25th and 75th width percentiles and profile intervals for η,κ. If the curves differ only through a wider `W` but their optimum centres do not move, width describes easier/harder shots and **does not by itself justify a width-conditioned aim**. A route above the ~72% fixed-band ceiling is credible only if a *genuinely pre-decision* width predicts a centre displacement of at least **10 ms across the interquartile range** and an adaptive offset policy improves held-out policy-success probability by **≥5 points**, with a 97.5% lower bound >+2 points in later independent sessions. This one 100-shot session is discovery/calibration for that policy, never its validation.

## 5. Passive network features and validation partition

`net_join.py` currently computes proxies, not decrypted input or server timing. **No network feature is confirmatory in the first single session**, because no session can be held out and packet identity is unverified. Freeze packet parsing/peer selection **without inspecting grade labels**. Before any network claim, verify pcap link type and captured length, nonempty UDP ports/time fields, stable clock alignment with shot records, independently identify the game flow (not merely the top public peer), and validate the input-bearing packet signature against random-offset events and no-input windows. At 42-byte snaplen those checks may fail; missing fields are missing, not zero.

For a later **≥5 independent-session, ≥30 graded network-feature shots/session** extension, the two *conditional* confirmatory candidates are: (C1) `rtt_court_delta = nearest_release_ICMP_RTT − nearest_press_ICMP_RTT`, only if the court endpoint is independently verified and paired ping coverage is ≥80%, with preregistered positive association to LATE residual; (C2) `send_lag_delta = release_input-bearing_send_lag − press_input-bearing_send_lag`, only if the packet classifier is validated before labels and feature coverage is ≥80%, also predicted positive. The present `first non-modal packet` rule does **not** pass that identity condition by itself. `rtt_gateway_delta` is a negative-control/local-congestion descriptor; `send_lag_release`, `send_phase_press/release`, `srv_phase`, and unvalidated `send_lag_delta` are exploratory. An inbound packet mode is not a demonstrated server tick.

For C1/C2, leave out **one entire session** at a time. Fit the base ordinal model (D, A, onset, shot order) and each one-feature extension only on the remaining sessions; freeze feature transformations, missingness handling, and any packet classifier on training data. Predict all verdicts in the held-out session. Require positive log-score improvement in at least **4/5** held-out sessions, a session-bootstrap **95% lower bound above zero** on pooled improvement, Holm-adjusted p<0.025 across C1/C2, and at least a **20% reduction** of fitted conditional sigma on training sessions before calling a network feature a useful noise explanation. A single in-sample `net_join.py` LR p<0.05 never qualifies. Both C1 and C2 use measurements at or *after* release and can be explanatory without being available to choose that shot's aim. Even a qualified ICMP/packet proxy is an association, not a server timestamp, one-way-delay proof, or directly shippable control input.

## 6. Stop and build decisions

| Outcome | Prespecified decision |
|---|---|
| Hook not armed, join coverage below gate, multiple dev draws above 2%, local first-stage CI not within [0.8,1.2], or grade attrition differs by >10 points | **Stop the clock/noise inference.** Preserve raw data; first build/repair the logging, draw identity, scheduler/command delivery, or capture validation indicated by the failed gate. No beta/sigma/ceiling claim from this run. |
| 100 shots with broad band/sigma profiles or FF uncertainty | **Continue the already planned block to 200**, regardless of which arm looks better. Do not ship from an interim 100-shot grade contrast. |
| Fixed-band model fits, but 95% upper `p_max` remains ≥0.80, width/actionability is unresolved, or network has no held-out validation | **Inconclusive**, not “ceiling confirmed.” Gather independent sessions/ground truth rather than tuning an unvalidated +7 ms or 0.45/40 setting. |
| Across ≥200 calibrated graded shots **and independent validation sessions**, fixed-band profile 95% upper `p_max<0.80`; width-conditioned policy 97.5% upper gain <+3 points; FF no-sweep 97.5% upper gain <+3 points; evaluable C1/C2 held-out tests have 95% upper log-score gain ≤0 and upper sigma reduction <20%; model calibration holds | **Ceiling confirmed for this spot/pipeline**, not for the game generally. End the variance hunt for a client-side timing tweak; retain the measured limit and stop speculative feedforward/aim changes. Missing or invalid network features make this row inconclusive, not a negative test. Non-significance alone never satisfies this row. |
| Verified arm-1 gain clears the no-sweep shipping gate, or verified pre-decision width clears its held-out adaptive-aim gate | **Build only the corresponding control mechanism**, then re-run the same fidelity and grade checks on a production-equivalent path. A settings-only .45/40 change is not that mechanism. |
| A qualified network feature clears its ≥20% sigma-reduction/held-out gate | **Build measurement/packet-identity instrumentation first**, not an aim controller based on post-release data. A subsequent pre-decision predictor needs its own randomised intervention before shipping. |

The result report must publish the complete attempt funnel, all ambiguous/missing joins, first-stage slopes, planned and actual offset distributions, arm assignment/actual F, category counts by offset bin/arm, profile intervals, width eligibility, capture/peer checks, and every predeclared held-out score. Keep observational legacy fits separate from these randomised results.
