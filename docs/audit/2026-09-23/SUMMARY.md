# Full audit summary — 2026-09-23

**Decision: blocked for paid-beta release approval; needs changes.** This is a read-only audit of the dirty NexusVision checkout and dirty Chiaki fork. Only the eight area reports and this summary were written; no product source/settings were changed, no launcher/installer/update was run, and no live service was contacted. Claude edited/rebuilt parts of both trees concurrently. Each area report pins its observations to source or binary hashes; a current package must be assessed again as one coherent unit.

The retained master gates remain separate from the new findings: **M-01** (the current signed package is not the revised source/build unit), **M-14** (the elevated update path needs end-to-end proof), and other open master items are not silently closed by source-only repairs. The current package passes its own integrity check (**577 verified files, exit 0**), but A6 rechecked four packaged native binaries against different current build bytes and five of 46 packaged sidecar source hashes against different current source. Integrity of yesterday's package is not freshness or reliability of today's fixes. The 02:28:59Z `OrionStream` exit-1 incident is real but its initiator remains **unidentified**; the owner's Options presses are temporal observations, not causal proof. New fork exit breadcrumbs improve future diagnosis but do not reconstruct the lost old incident.

## Evidence ledger and immediate gate

- **A1 native scratch policy/engine:** rebuilt policy tests 58 passed; copied engine fixtures reproduced A1-001/002/003. The original mixed-generation native crash was discarded as source-failure evidence.
- **A2 controller/UI:** 52 focused Python tests and 167 existing native tests passed, but the native binaries predate relevant source edits and are not package proof.
- **A3 fork:** current real named-pipe harness at SHA-256 `7FD3EE72FED5A56A38531E7AD3B6877A4C07AAAAAEB7D395F2C891A6A8702D05` passed 9/9 in three fresh processes; old failing and old six-pass builds remain separate historical populations. The 165-test fork unit suite passed. Newly replaced deployed GUI binary was **not launched** here.
- **A4 sidecar:** 225 focused tests passed, two skipped; Astra reader/CV repeat passed 240 after one timing-only first-run failure. No live capture or console was exercised.
- **A5 backend/website/lease:** 48 mocked backend, 42 Worker and 21 native heartbeat-policy tests passed separately; their coupled paid-provisioning and outage transitions remain untested.
- **A6 package:** 82 packaging tests passed; existing signed package verifies 577 files; copied updater/archive fixtures reproduced transaction faults. The package is stale relative to current edited source/build artifacts.
- **A7 broad Python (network/app launch guarded):** **4,247 passed, 8 failed, 14 skipped, 6 deselected, 6 xfailed, 4 xpassed; exit 1.** Six failures are host-disk test fixtures (all six pass under deterministic ample-space fixture); one is an old 50 ms R2 default assertion contradicting current accepted 0 ms pass-through; one is a reproducible diagnostic thread-name race. The historical “~30 failures” cache is **not** a current failure count: 44 stale nodeids, three now passing, five disk-fixture failures among 52 old root entries. The abandoned-publish native SHM fixture failed 1/20 frozen-unit runs.

**Release closure:** freeze the concurrent edits, rebuild a coherent native/sidecar/fork deployment unit, repair the high-impact transitions and updater transaction, add their cross-component regressions, make the broad offline suite and egress guard clean, then run **Standard and StrictSecurity** on that exact unit and a disposable install/update/rollback canary. No green subset or signed-manifest match substitutes for those gates. This audit does not authorize a production release.
