## Findings, LOW → CRITICAL

Each reproduction was on the reviewer copy or archived-source fixture. “Required test” is the closure condition, not a claim already met.

### LOW — CSEC-01: exact-byte candidate-sheet error, not a demonstrated env unlock (P+S)

`OrionNative.exe` contains UTF-16LE `ORION_LEAD_FLOOR_MS` once at offset **2084274** and `ORION_LEAD_BIAS_MS` once at **2084318**; the sheet's “no strings” assertion is false. `AutomationCore.dll` contains the bias marker once at offset **680738**, in diagnostic prose (`AutomationEngine.cpp:2825`), but no floor or onset-FF marker was found there. The native markers are calibration error copy (`OrionAppController.cpp:9354-9358`); actual lead environment reads in `AutomationEngine.cpp:2633-2654`, and onset-FF reads near `:1613-1670`, are `#ifndef ORION_PRODUCTION_BUILD`. Production `LeaseGate.cpp:33-43` returns enabled regardless of environment. Impact: evidence quality, not a proven runtime bypass. Fix sheet wording and add a compiled production negative test; verify setting these variables leaves the actual automation config and fire gate unchanged.

### LOW — CSEC-02: unreachable first-run signature bootstrap branch (S)

`SecurityManager.cpp:384-390` requires `!exists(settings)` outside then `exists(settings)` inside. The inner branch cannot execute. `OrionAppController.cpp:1955-1979` instead loads, saves and signs when the signature is absent, so this dead branch is not proof of first-launch lock. Impact: misleading defense/recovery reasoning. Fix/remove the dead branch; test first-ever profile and missing-signature-after-existing-profile separately.

### MEDIUM — CSEC-03: unsigned-to-manifest *extra-file* gap in signed update (F+S; release blocker)

A fixture-signed ZIP containing unlisted `version.dll` and `platforms/qinjected.dll` completed the dev-profile updater staged-helper flow; both files were present in the copied install. `SecurityManager.cpp:578-610` checks listed files; `UpdaterArchive.cpp:583-586` copies the whole staged tree. Independent package verifier mutation also returned `ok=True errors=0 warnings=1` for an unmanifested DLL. This does **not** show an unsigned attacker can publish an update; precondition is a signing/pipeline mistake or compromised signer. It does violate the AGENTS “no unmanifested runtime files” release rule and leaves DLL-loading ambiguity. Fix exact signed inventory enforcement at stage and post-apply; require C20 to refuse with unchanged inventory.

### MEDIUM — CSEC-04: verifier trust-model mismatch and downgrade input (F+S)

`tools/verify_release_integrity.py` accepted a fixture update manifest with an unknown key ID and its own in-manifest public key (`ok=True errors=0`); production native trust uses only the embedded ID/key and native updater tests reject unknown IDs. This is a **Python gate false positive**, not a native signature bypass. Separately, `updater_main.cpp` passes caller `--current-version` into the downgrade decision instead of deriving a verified installed version; the independently inspected F7 fixture showed a signed older build can be installed when that CLI value is forged. Preconditions include a previously signed old artifact plus install write/elevation; no earlier production release was proved. Fix the Python verifier to use the production pinned keyring and derive current version from the installed signed manifest; test unknown-ID rejection and forged version rollback refusal. The frozen manifest's empty artifact URL also requires a newly signed/published record and exact hash capture before deployment.

### MEDIUM — CSEC-05: settings signature is recoverable but can be self-repaired after tamper (S; runtime effect U)

If `settings.json.sig` is deleted, `OrionAppController.cpp:1955-1979` re-saves current settings and signs on next startup; `DebugPage.qml:368` exposes “Sign Settings” and `OrionAppController.cpp:8748` signs the current file. This refutes the new Gemini report's unconditional “unrecoverable settings lock” claim, but means signature deletion plus settings edit can launder a local config change. Existing signature/hash mismatch does lock, and `automationSecurityAllowed()` (`OrionAppController.cpp:11255-11275`) still requires authentication, no security lock, and lease permission: **no license/fire bypass proved**. Fix one-time bootstrap marker/atomic save+signature and restrict/manual-audit re-sign; verify tampered config cannot be silently re-signed while authentication/lease gates remain closed.

### MEDIUM — CSEC-06: heartbeat lease lacks request/epoch freshness binding (S; runtime replay U)

`backend/lambda_function.py:1845-1869` signs license key, machine ID and expiry. The heartbeat request/response path carries no request nonce or account/session epoch; an old same-key/same-machine signed response could be replayed before expiry or across backend state change until the client's local freshness/expiry logic stops it. It **cannot** authorize a different signed key or machine, contrary to a broader claim. Fix signed nonce/session epoch and monotonic freshness; test replay after revoke/sleep/clock jump and recovery at the actual automation gate, not merely a UI label.

### HIGH — CSEC-07: default Program Files update elevation decision is false (P+F+S; release blocker)

Archived `OrionAppController.cpp:5874-5877` uses `QFileInfo(installDir).isWritable() && QFileInfo(parent).isWritable()` to decide `runas`. An independent medium-integrity PySide6/Qt **6.11.1** probe on this host returned `C:\Program Files\Git: exists=1 dirWritable=1 parentWritable=1 elevate=0`, and `C:\Windows\System32\drivers` likewise; `icacls C:\Program Files` grants Users RX. The packaged Native and Updater manifests both say `asInvoker` (Windows `mt.exe`, exit 0). This corroborates F7-001's Qt 6.8.0 result, but an actual owner VM install/update was **not** run. Impact: default install likely never requests UAC and staged update fails for insufficient access; emergency/key-rotation recovery is not reliable. Fix real create/delete write probe or explicit updater elevation with safe fallback; prove mandatory signed update succeeds from both standard-user and UAC-admin VM installs, and decline leaves old hashes intact.

### HIGH — CSEC-08: foreign file handle can leave mixed old/new install after rollback (F+S; release blocker)

On reviewer TEMP with a separate fixture signing key, the inspected staged-updater C27 reproduced `Update failed AND rollback failed (Could not overwrite: ...plugins\retired.dll)`. Inventory after failure had **new** `Qt6Core.dll`, `UpdaterCore.dll`, `release_manifest.json`, `.sig`, but **old** `plugins/retired.dll`; before digest `c58cf3c28aeb8754`, after `2b5e6b822fa7ab7c`. `UpdaterArchive.cpp:224-229` removes before copy; `restoreTree:588-601` returns at the first failed overwrite. A6 injected self-fault rollback success does not cover this handle. Impact: integrity lock and manual repair instead of an atomic old/new signed unit. Fix skip already-identical restore entries, retry/rename-aside, preserve durable backup/recovery marker; hold/release foreign handles at every apply/prune point and demand exact old or exact new inventory.

### HIGH — CSEC-09: single mutable device binding under a two-device policy (F+S)

Mocked `max_devices=2`: activate A → 200, activate B → 200, then validate A → `403 device_mismatch` (`test_codex_security_fixture.py`). A sold two-PC entitlement would silently evict PC A. Fix a set of up to N independently bound devices with atomic capacity enforcement or advertise one active device only; test both PCs concurrent and revocation/rebind. Severity is conditional on the sold policy.

### HIGH — CSEC-10: kill mutation completes after audit write failure (F+S; release blocker)

`handle_kill()` (`backend/lambda_function.py:1125-1170`) updates the global kill row **before** `audit()`. `audit()` defaults `required=False` and swallows a failed audit-table write (`:417-459`); `audit_attempt_or_refuse()` is not called. In a mocked audit outage, `/api/admin/kill` returned 200 and the global flag became true without a durable audit row. Same ordering exists on license revoke. Fix required pre-mutation attempt audit, idempotent completion audit and failure handling across every destructive route; test audit-table failure leaves state unchanged with 503. AGENTS explicitly makes unaudited destructive action a blocker.

### HIGH — CSEC-11: custom install can place LocalSystem service under a writable parent (P+S+ACL observation; VM exploit U; release blocker)

Archived `installer/orion.iss` allows choosing a directory, registers `{app}\packet_bridge\VeniceNetSvc.exe` as `LocalSystem`, and does not harden `{app}` ACL; service ACL hardening is not directory hardening. On this host `C:\Program Files` has Users RX, while a reviewer-created custom-directory fixture under TEMP inherits current-user Modify. The service uses an adjacent driver DLL. If an install is allowed under a non-admin-writable parent, a non-admin actor with directory write may replace service-loaded bytes; no actual custom install, second user, SCM restart or SYSTEM execution was performed. Fix Program Files-only install **or** explicit SYSTEM/Admin full + Users RX ACL for service/driver/app binaries and reject writable ancestry; verify in a two-standard-user VM and preserve unrelated files on uninstall. This is more than the F7-003 source hypothesis, but not a proven VM privilege escalation.

### CRITICAL — CSEC-12: owner staff bearer can disable TOTP and rotate break-glass secret without step-up (F+S; release blocker)

Archived `resolve_owner()` (`backend/lambda_function.py:3481-3513`) calls `owner_totp_ok` only for the admin-secret route. For a role=owner staff bearer it checks role but no fresh TOTP. `handle_admin_config()` (`:4819-4838`) then accepts `totp_disable` and `rotate_admin_secret` without action-specific step-up. Two **mocked** tests used an already-enrolled owner row bound to `MACHINE-A`, logged in with staff ID + client-declared machine ID + timestamp/nonce (no TOTP), set `owner_totp_required=True`, and observed status 200 for both actions. The rotate response contained a newly generated secret; its value was neither printed nor saved. `handle_staff_login()` (`:1523-1580`) also requires no password/possession proof once the row is enrolled; machine ID is a submitted string, not cryptographic device attestation. This amplifies a known owner-ID/machine-ID exposure, though no real owner ID or live exploit was tested. LOW is not an adequate severity for removal of MFA and takeover of the recovery secret. Fix authenticated staff login with independent possession proof, and require a fresh owner TOTP or equivalent independent step-up for disable/rotate regardless of bearer; fail closed and audit intent before mutation. Test wrong/right machine claims, stolen bearer, expired TOTP, disabled owner, audit failure and both sensitive actions.

### CRITICAL — CSEC-13: warm cached “kill off” authorizes fresh leases during selective read outage (F+S; release blocker)

`get_global_kill()` (`backend/lambda_function.py:494-506`) returns `_LAST_GLOBAL_KILL` on a config read error. With prior cached `(False, '')` and a selective global-kill read outage, mocked `/api/license/check` returned 200 and a signed lease. If owner engaged kill in the backing store after the cache was last read, this container keeps minting authority without learning that state; a fresh cold container fails closed, so the bug is warm-state-specific. Fix deny new/renewed lease on unknown kill state (or bounded, versioned fail-closed cache protocol); test warm disabled→owner kill→selective outage and actual lease/fire denial plus recovery.
