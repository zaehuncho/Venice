## Owner VM closure procedure (never on the developer machine)

Use a disposable two-account Windows VM (standard user plus UAC admin), clean snapshots, **signed rc2** package/installer and an owner-controlled staging endpoint. Freeze old/new package, ZIP, manifest, and installer SHA-256 before tests; record exact filenames, commands, stdout/stderr, exit codes and `orion_updater.log`. Do not substitute the frozen rc1's empty-`artifact_url` update manifest. Restore a VM snapshot between independent negative cases. A failure in any criterion keeps release **BLOCKED**.

1. **RT-HIGH-01 — install boundary/uninstall.** From clean VM, try an admin install with `/DIR=C:\Users\<standard-user>\Venice`; Setup must refuse before `VeniceNetSvc` registration. Install to the default directory, then record `icacls "C:\Program Files\Venice" /T`, `sc.exe qc VeniceNetSvc`, `sc.exe sdshow VeniceNetSvc`, and `Get-Item -Force "C:\Program Files\Venice" | Format-List FullName,Attributes,LinkType,Target`. As the *standard* account, attempt create/replace in `C:\Program Files\Venice\packet_bridge\VeniceNetSvc.exe` and its adjacent DLL; both must be denied, with the old SHA-256 unchanged. Probe a pre-existing weak-ACL or junctioned `Venice` folder on a throwaway snapshot; reject the release if it remains user-writable after install. Test service start only against the protected, unmodified binary and verify no privileged action can be redirected through a user-writable file. Put `foreign.keep` in the install folder as admin, uninstall, and require that exact file/hash remains (and that no unrelated Program Files sibling is removed). Record default-No, Yes, and silent uninstall data results separately.
2. **RT-HIGH-02 — actual UAC.** On a default `C:\Program Files\Venice` rc2-old install, snapshot the full runtime inventory excluding the updater's own log. As standard user initiate the signed rc2-new update through Venice: require a UAC credential prompt, successful exit/relaunch and exact new manifest/signature/file hashes. Repeat as a medium-integrity admin: require UAC consent and exact new hashes. Restore the old snapshot; decline UAC and require the launcher stays running, the signed file inventory remains **exact old**, and no staged updater remains active. Record the update state shown to the customer.
3. **RT-HIGH-03 — held retired DLL C27/C28.** Install exact old unit on the VM; arrange a signed new unit that retires one DLL. Hold the old retired DLL open with a foreign process denying delete sharing, then invoke the owner-controlled offline updater fixture (C27) from a *copy* of the install. Expected: refusal before backup/apply and exact old inventory. Release the handle and run C28: expected exact new inventory. Also inject a late lock after preflight and the existing `--inject-failure-after-prune` development fixture: require exact old after rollback or a durable recovery marker plus retained backup and no relaunch; repair only from the owner-verified old/new installer, then verify exact hashes before clearing the marker. Repeat with a VM power cut during copy. **Do not accept a mixed state as closure.**
4. **RT-MED-08 — trust/inventory.** With a development-profile updater and disposable signed fixtures, repeat C20 (signed ZIP with an extra Qt plugin/DLL) and C25 (older signed manifest plus forged `--current-version`); both must refuse without changing the install. Repeat unknown key ID with self-supplied public key, wrong key, non-HTTPS URL, wrong HTTPS origin, and 30x redirect from the pinned manifest endpoint; production binary must refuse each. Verify positive rc2-new update from the pinned owner-controlled HTTPS endpoint, then compare every installed signed file and reject all unmanifested runtime files. Run `tools\verify_release_integrity.py --package <signed-rc2-package> --update-manifest <signed-final-update-manifest> --artifact <signed-rc2-zip> --strict-warnings` against a **disposable copy**; require exit 0, then add one extra DLL to another copy and require nonzero. For server-shard, separately run `tools\security\pack_lethe_release.py --verify-only --input <copied-server-shard> --server-shard` and inventory-diff every file.
5. **CL3-F7-007 — owner shutdown.** On separate old-unit snapshots, leave `OrionStream.exe` orphaned, and separately demand-start `VeniceNetSvc` via Meter Delay. Upgrade with signed new unit. Require the installer/updater to stop the relevant owner before replacement, SCM reports `STOPPED` for the service during apply, no locked-file prompt, exact new hashes, and a working service after the next deliberate start. Refusal on stop timeout must leave exact old hashes. Capture `sc.exe queryex VeniceNetSvc` and updater log before/after.

After all five rows pass, integrate Claude's concurrent changes in a new isolated **rc2** release candidate and run the repo's Standard and StrictSecurity scripts on that exact frozen unit. Re-run the two-user VM matrix on the exact publishable installer/manifest/ZIP. Record installer Authenticode status; neither this source patch nor a test-key/dev-profile fixture approves an unsigned public installer.
