### P7-01 — LOW — preview shared-memory object permissions are implicit; live ACL unmeasured — needs changes

- **Path / affected:** `shm_frame_bridge.py:203-243` creates a named mutex, mapping, and event with default Windows security attributes; `native_orion/src/SharedMemoryFrameReader.cpp:87-118` reads the mapping. Names are generated per session (`RemotePlaySession.cpp:3351-3358`), but are not an authorization secret.
- **Impact:** Another process under a permitted Windows SID could potentially open or interfere with preview objects. The preview path is display-only here; I found no proof that altering this mapping alone grants shot/fire authority. The cross-user ACL and actual object owner were not measured.
- **High-level reproduction:** On an isolated, non-console preview fixture, inspect the live mapping/mutex/event DACL under the launcher account and a second standard account; attempt read/write/open without sending game input.
- **Required fix:** Specify and verify the intended owner/SYSTEM DACL, use unpredictable per-session names only as collision protection, and treat every mapped header/pixel as untrusted. Do not promote preview data to detector authority.
- **Verification:** The owner can read; a second standard account cannot; corrupted headers are rejected without crash or automation; preview recovers after object loss.
