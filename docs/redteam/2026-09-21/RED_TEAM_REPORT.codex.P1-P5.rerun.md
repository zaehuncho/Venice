## Ranked findings — lowest to highest

### P2-01 — MEDIUM — production timing A/B remains environment-selectable — needs changes

- **Failure path / affected:** `C:\Users\aaron\Desktop\NexusVision\native_orion\src\AutomationEngine.cpp:1602-1656,17597-17677` parses `ORION_ONSET_FF_*` and `ORION_ONSET_FF_AB` without the production guard applied to `ORION_DEV_LATE_CARRY_AB` (`:1661-1683`) and the fire-offset sweep (`:17278-17348`). The A/B can use a 40 ms clamp instead of the default 10 ms and can select two-sided correction. The reviewed `OnsetFeedforward.h:38-42` calls the feature zero-mean, but its one-sided decision at `:137-150` is only zero on early onsets and advances late-onset shots; it has a negative mean when applied.
- **Impact:** A locally inherited experiment setting can change customer fire deadlines and confound timing diagnosis. This is not an entitlement bypass. The default correction has source bounds, but the live A/B did not establish benefit.
- **High-level reproduction:** In a copied production-build fixture, compare scheduled-fire decisions with clean environment and with two valid A/B arms after four same-bucket onset observations; inspect `ONSET FF` arm, offset, and learner-fence logs. The current dev unit tests cover parser syntax but not a production no-experiment guarantee.
- **Fix / verification:** Compile out or authenticated-policy-gate experiment overrides in production; retain only the approved bounded default. Test production and dev builds separately, include a zero/control arm, and show learner invariance under displaced shots.

### P4-01 — MEDIUM — exceptional feedback-sender exits lack an explicit terminal publication — needs changes

- **Failure path / affected:** `C:\Users\aaron\Desktop\chiaki-ng-src\lib\src\feedbacksender.c:867-869,881-904,1089-1091,1233-1236`. An initial/reacquire mutex error returns directly, and unexpected condition-wait errors break the sender loop without setting `should_stop` or a session-level terminal reason. `:405-453` reports cancellation to a delivery waiter only when `should_stop` is visible. A later wait can therefore time out rather than identify a dead sender; the bridge's timeout branch at `gui/src/orioninputbridge.cpp:298-310` treats exact `TIMEOUT+NONE` as a soft, session-preserving fault.
- **Impact:** Rare internal synchronization failure can be diagnosed and recovered as transient input loss while the sender is dead. This is a source-proven state-publication gap, not a reproduced Windows kernel fault.
- **High-level reproduction:** In a fork-only sender fixture, inject each lock/condition failure before an owned `MustDeliver` packet; observe the waiter result, bridge action, and whether a terminal session state is published.
- **Fix / verification:** Route every sender exit through one terminal-state publisher, wake all waiters, and make the bridge distinguish sender death from a packet deadline. Each injected exit must either restore a verified neutral/human route or visibly terminate the session within a bound.
