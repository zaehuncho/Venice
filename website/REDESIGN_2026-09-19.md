## Live vs repo, before touching anything

`curl`-ed `https://zaeorion.com/` plus its CSS/JS/legal pages and diffed them against `website/public/`.
**The live site and the repo were identical.** The only difference in every HTML file was the
Cloudflare bot-management script Cloudflare injects at the edge (`/cdn-cgi/challenge-platform/…`),
which carries a per-request ray id and timestamp — that is why the live sha256 never matches the repo
(7353f10d one minute, d9467ded the next). Strip that one `<script>` and the bytes are equal:
`index.html`, `styles.css`, `app.js`, `legal.css`, `terms/privacy/refunds.html`, `favicon.svg` all matched.
Nothing live was newer, so nothing live was lost.

Side note for the owner: that injected script is inline, and the site's CSP (`script-src 'self' https://js.stripe.com`)
blocks it, so it never runs and it shows up as a console error on the live site (Lighthouse best-practices 89 on
live because of it). Turning off "JS detections"/Bot Fight Mode for the zone, or adding a CSP nonce, would clear it.
Not changed here — it is a zone setting, not a repo file.

## Pricing card: the Discord + server gate

Built to the contract in `docs/WEBSITE_TRIAL_AND_AUTOJOIN_2026-09-19.md`. A three-step indicator
(1 Connect Discord → 2 Join the server → 3 Trial or subscribe) sits above four states:

| State | Shown |
|---|---|
| `authenticated:false` | only **Continue with Discord** → `/auth/discord?return_to=%2F%23pricing`, sub-line "Free 3-day trial · no card needed". No trial or buy button. |
| signed in, `inGuild:false` | **Join the Venice Discord** (new tab, `joinUrl`, falls back to the invite) + **I've joined — refresh** (re-fetches `/api/checkout/config`). No trial or buy button. |
| signed in, `membershipUnknown:true` | buttons stay, plus the note "We couldn't confirm your Discord membership. If you haven't joined yet, join here first" (the server re-checks and fails closed at purchase time). |
| signed in, `inGuild:true` | **Start free 3-day trial** (`POST /api/trial`, `credentials:'same-origin'`, `Content-Type: application/json`, body `{}`) + **Subscribe — $25/month** (existing embedded Checkout), and "Signed in as {username}". |
| after `code:"issued"` | success state: "Your free trial has started", the server `message` verbatim, and **Get your one-time code** → `/connect`. |

Error handling: every failure shows `payload.message || payload.error` inline (never an `alert()`, never the raw
code). `join_required` — matched on `error` **or** `code`, from the trial POST or the checkout POST — switches to the
join state using `payload.joinUrl`; the checkout dialog closes first and the page scrolls back to pricing.
`auth_required`/401 navigates to the Discord sign-in. `already_claimed` shows the message with no retry (the
subscribe button is right there); `dm_failed`, `rate_limited`, `membership_unavailable`, `unavailable` and network
failures get a **Try again** button (in the dialog for checkout failures). Returning from the Discord tab
re-checks membership once, quietly.

Backwards compatible: against today's deployed Worker (no `trial`/`inGuild` fields) the card lands in the
signed-in state and the trial button opens the Discord invite with the note "run `/claim_trial` there".

**Assumption to confirm:** `trial` is read as "the website trial route is configured" (that is what
`trialConfigured(env)` returns in the new Worker), not "this user is eligible".

All four states are in the markup and only their visibility is switched, inside one CSS grid cell, so the card's
height never changes when the state resolves — measured identical at 259.67 px in all five states, which is why
CLS stays at 0 even when Discord bounces the user back to `/#pricing`.

## Design and performance notes

- **Typography**: Geist Variable (SIL OFL), latin subset, self-hosted, one 29.4 KB file, preloaded, `font-display: swap`
  with a metric-matched Arial fallback (`size-adjust: 105.85%`, `ascent-override: 94.94%`, `descent-override: 27.87%`,
  computed from the real font metrics) so the swap does not move text. Smallest text on the page is 12.5 px.
- **Brand**: the blue V is now an inline SVG traced from `orion.png` (98.2 % IoU against the original alpha mask),
  used in the header, hero emblem, footer, flow diagram, 404 and legal pages. That removes the 49 KB `orion.png`
  preload from the home page. `orion.png` stays in place because the Worker-rendered pages use it.
- **Starfield**: same `<canvas id="starfield">`, rewritten. It is painted once, then repainted only while the
  pointer parallax is settling — 30 fps cap, pixel ratio capped at 1.25, idle at rest (the old version repainted the
  full viewport 30×/s forever). Deterministic star field in normalised coordinates, so a resize rescales the same
  sky instead of reshuffling it. No parallax under `prefers-reduced-motion`, `pointer: coarse` or Save-Data.
- **Motion**: hero entrance, a breathing glow, two signal pulses in the flow diagram, hover lifts — all inside
  `@media (prefers-reduced-motion: no-preference)`. Verified: with reduced motion the page has **0** running
  animations. A CSS scroll-driven reveal was built and then removed — it leaves below-the-fold sections at
  opacity 0 in full-page screenshots, which would make the page look broken in review captures.
- **Accessibility**: semantic landmarks, skip link, labelled nav/lists, `aria-current="step"` + screen-reader step
  status on the progress indicator, `role="alert"` on plan errors, focus moved to the success panel after a trial
  claim, visible focus rings, `role="img"` + description on the diagram, Escape/outside-click closing the mobile
  menu. Contrast is ≥ 4.5:1 everywhere, including white on the button gradient (4.70 at the lightest stop).
- **Responsive**: no horizontal overflow at 360 / 390 / 768 / 1024 px (scanned programmatically, zero offenders).

## What changed, and why

**Product first, story second.** The page used to open with a slogan and make you scroll past a features
grid to reach the buy box. Now the order is hero → **Pick your plan** (the purchase gate) → What Venice does →
How it works → FAQ. The buy area is the second thing on the page, which is what the reference does.

**Plain sentences instead of marketing couplets.** `Dial in your release. / Keep it consistent.` (with the
second line in a blue gradient) is gone. The hero now says what the thing is, what it runs on, and what it
costs, in two sentences:

> **Jump-shot timing for NBA 2K27 on PS5**
> Venice is a Windows app. You start the shot; it reads the in-game shot meter over a capture card or PS5
> Remote Play and times the release. $25 a month, flat. The first 3 days are free and need no card.

Every other heading is a label, not a line of copy: *Pick your plan*, *What Venice does*, *How it works*, *FAQ*.
Section intros are one factual sentence each. No gradient words anywhere on the page.

**A facts strip under the hero** — the shape of the reference's stats strip, filled only with things that are
true of the product rather than social proof: `$25/month · flat price, no activation fee`, `3 days free · no
card needed`, `Remote Play or capture card · 60 Hz card recommended`, `One PC at a time · 3 free PC resets`.

**Trust badges under the buy area**, all verifiable: *Secure checkout by Stripe · Cancel anytime · Works with
capture card or Remote Play · Setup help in Discord.*

**Compact utility header**: logo, four links, and the account control on the right (see below). 56 px tall,
opaque, always bordered — no scroll-state fade.

**Flatter, denser visual language.** Removed: the hero glow, the glowing V emblem, the "arc of light" horizon,
the radial glow behind the price card, the card top-edge shimmer, the gradient-border price card, the 84 px
gradient "60", the frame-tick graphic, the animated signal-flow diagram with its two pulses, the hero entrance
animations, the breathing glow and the hover lift. Radii went 20–26 px → 12 px, the hero headline 96 px → 48 px
max, the price numeral 88 px → 44 px, section padding ~116 px → ~68 px, the shell 1160 px → 1120 px. Panels are
now one flat surface with a 1 px border; the feature grid, the facts strip and the steps use hairline dividers
instead of floating cards. Spacing sits on an 8 px rhythm. The only decorative light left is one soft blue
gradient at the top of the page, and the star canvas, whose stars were dropped from alpha 0.20–0.65 with halos to
alpha 0.09–0.29 with none, so it reads as texture rather than a space scene.

**The gate is unchanged in behaviour** and is now the visual centrepiece of the pricing section: a two-column
buy block, plan facts on the left, the Discord gate on the right.

**404 copy** — `That page missed the window. / Return to Venice and reset the play.` → `Page not found. / That
page does not exist. Head back to the Venice home page.` **`legal.css`** was flattened to match (h1 4.2 rem →
2.6 rem, 24 px radius → 12 px, gradient panel → flat). The legal *body text* is still byte-for-byte what the
legal agent wrote.

## What I deliberately did **not** copy from the reference

The reference's credibility comes from numbers Venice does not have. None of it was copied, imitated or
mocked up:

- **"2,000+ Active users", "2,973+ Reviews", "4.9 Average rating"** — we have no audited count of either, and a
  made-up one is a lie that a single screenshot of the Discord member list disproves.
- **Five-star ratings on each product** — there is no review system, so any stars would be decoration
  pretending to be data.
- **The floating "LIVE PURCHASE — someone just purchased Optic V8, 2 hours ago" toast** — fabricated purchase
  events, and on a page that takes card details it reads as a dark pattern.
- **"Trusted by …" claims** of any kind.

What we took instead is the *shape*: a four-up strip of short facts under the hero, and a row of small badges
under the buy area — filled with product facts ($25/month, 3 days free, Remote Play or capture card, one PC /
3 resets; Stripe, cancel anytime, capture card or Remote Play, Discord support). The single
`<!-- OWNER: add real clips/vouches here … -->` slot between Pricing and Features is still the only place real
proof goes, and it is still empty.

The verifier now **enforces** this: a new assertion fails the build if a user counter, a star rating, a review
count, a "trusted by" claim or a purchase toast ever appears in `index.html`.

## Light/dark toggle — not built, on purpose

The brief allowed it "only if it costs nothing in complexity". It does cost: `styles.css` also skins the
Worker-rendered `/discord` and `/connect` pages, the legal pages and the 404, and roughly sixty colour values
are `rgba(255,255,255,…)` overlays that only work on a dark surface. A real light theme means re-deriving and
re-contrast-checking all of them across five page types. The page keeps `color-scheme: dark` and the dark
default. If the owner wants it, it is a focused follow-up, not a free toggle.

## Performance

**Inline stylesheet.** Lighthouse's only render-blocking item was `styles.css` (est. 159 ms on mobile). The home
page now carries the sheet inline (CSP already allows `style-src 'unsafe-inline'`), which removes one round trip
from the critical path: 5 requests total (`/`, font, `app.js`, `/api/checkout/config`, `favicon.svg`).

**Font: same file name, 8 KB lighter.** The site uses weights 400–650 only, so the Geist variable font was
re-instanced with `fontTools.varLib.instancer` to a **400–700 weight axis**: 29,400 → **21,392 B**, same 288 glyphs,
same cmap, identical hhea/OS/2 metrics (so the metric-matched fallback still lines up). It ships under the existing
name `fonts/geist-latin-wght-normal-v1.woff2` because the three legal pages (untouchable this pass) `preload` it by
that name; a browser holding the old immutable copy keeps a superset that renders identically. `@font-face` now
declares `font-weight: 400 700`.

**First paint of the stars rides the first animation frame** (`requestAnimationFrame(resize)`) instead of running
synchronously in the deferred script, so the page's first layout is no longer forced inside the script task
(Lighthouse's "forced reflow" insight cleared; TBT 90 ms → 0 ms on mobile).
