### Batch B — the free experiment: YUY2 instead of MJPG
The one change with real upside and zero code. We currently feed the detector **MJPG 4:2:0**
(chroma at half vertical resolution) **downscaled 1080p → 720p**. The green tip is a few pixels
tall, so we're destroying its colour twice. The audit's own biggest undetected bucket is
**875/4637 frames** bailing on `no_cap_anchor` — *when the green cap is faint*.

The code comment at `remote_play_orchestrator.py:~2637` says YUY2 (4:2:2, full vertical chroma)
gives a "sharper fill-top/green tip" and is A/B-able **without a rebuild**.

Set this before launching:
```
$env:ORION_CAPTURE_MJPG = "0"
```
Then run the **same shot count** as Batch A, same shot mix.

**Watch for:** stutter. YUY2 at 1080p60 is uncompressed (~250 MB/s over USB) and could make it
*worse*. If the preview stutters or fps drops, that's the answer — say so and we revert.

I'll diff the two batches on detection rate and landing quality.

### Batch B2 — feed the detector 1080p instead of 720p
The other half of the same problem. The card negotiates 1920x1080 and we **downscale to 1280x720
before detection** — while `simple_meter_reader`'s own pixel priors are declared AT 1080p
(`_REF_W, _REF_H = 1920.0, 1080.0`) and get scaled *down* to whatever we hand it. We throw away a
third of the resolution, then shrink the reader's native-resolution priors to match.

Set this before launching (and put MJPG back to default for a clean single variable):
```
Remove-Item Env:\ORION_CAPTURE_MJPG -ErrorAction SilentlyContinue
$env:ORION_DETECTOR_1080P = "1"
```
Same shot count, same mix.

**Watch for:** dropped detector fps or preview backpressure. 2.25x the pixels per detect. The
simple reader is ~0.6 ms so there should be headroom, but confirm rather than assume.

**If BOTH B and B2 help**, run them together as B3 — that is the configuration we would ship.
